## 5. Deviations from the plan (and why)

1. **Restore replaces the fresh app's starter team, its empty spaces and scanned AI-app entries** (the plan lists them as
   what an "empty app" may hold, not what happens to them). Keeping them would give two "Director"s and two "Team" spaces
   with the same names, which the editors forbid. `RestoreSettings.merge` receives the file's agents as the agents after
   the restore. The preview says so (`BackupTexts.STARTER_REPLACED`).
2. **"Validated like owner input" is `RestoreChecks` in `:data`**, not a call of `ProviderDraftValidator` / the agent
   manager / `MemoryRules`: `:data` cannot depend on `:framework` or `:memory`, and two of them are internal. An agreement
   test in the app pins them together. One difference on purpose: a cloud Anthropic/Gemini provider without a key is
   accepted (keys are never in the file). Scanned or listed metadata (AI-app labels, model display names, notes) is
   checked only where the app acts on it (package name, prompt link), so a backup of a phone never fails on a label a
   scan found.
3. **"Refused while an objective runs or a chat turn is live"** is the fresh-app rule: a fresh app has no objective and
   no chat, so none can run; the check is repeated inside the transaction, and the gate keeps new ones out (WP7).
4. **Two passes over the file** (check, then write inside the transaction, bound together by header hash and plaintext
   digest): the free-space check needs the size before writing, an invalid file is refused before any transaction, and
   memory use stays at one chunk (plus the record being read).
5. **`DetailedOwnerBackup`, `SaveOutcome`, `RestorePreview`, `RestoreOutcome`** added in data/backup: the screens need
   notes, settings kept back and a refusal known in advance, which core's `BackupSummary`/`SaveReport`/`RestoreReport`
   cannot carry (core is nobody's in wave 2).
6. **Tool titles bound late** (`ToolTitles`, `BackupWiring.useToolTitles`): the registry exists only with the graph, and
   `BackupWiring.production` is called before it (item 1 of section 2).
7. **Inspect is logged too** ("Backup file opened" with counts), so every operation of the port is in the log, as the
   K13 KDoc asks.
