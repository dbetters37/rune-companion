# Wave 2b: minors left after the review fixes

Every finding of the wave-2b security and Android reviews was fixed on p6/w2bfix (SEC-W2B-1, SEC-W2B-2, AND-W2B-1, AND-W2B-2,
AND-W2B-3, AND-W2B-4, AND-W2B-5), each with a test that failed before the fix. No minor finding is left open.

What remains are limits of the fixes, small and known, for the owners named:

| Owner | What | Why it is left |
|---|---|---|
| WP8 (optional) | A `TIMEZONE_CHANGED` receiver for routines. After a zone change the routine's alarm still goes off once at the old instant; the pass now realigns and starts nothing (AND-W2B-5), and the alarm moves to the new local time. A receiver would only save that one wake. | Manifest row (shared file of wave 3); not needed for correctness. |
| WP8 / WP14 | A restore that stops after Room's commit and before the settings write (AND-W2B-4) leaves the restored records with the fresh app's settings: the Director is repaired at the next start, but the file's local-only mode, daily limits, "Notify when work ends", "Calm" and its older seed version (the tools a newer version adds to older starter agents) are not applied. The restore's report never reached the owner in that case. | The safe direction (fresh settings, nothing relaxed). A journal of the merged settings in noBackupFilesDir would close it; not worth it for a window of one DataStore write. |
| WP10 | `BackupTexts.SETTINGS_NOT_RESTORED` is a new restore note ("... this phone's own settings are kept. Check them in Settings."): show it like the other notes on the Restore result. | New text from AND-W2B-4. |
| WP10 / WP14 | Folders shared through the picker's "Downloads" entry (ids `msd:<n>` on Android 14 as the device recheck measured, `raw:<path>` before MediaStore saw the folder, `downloads` on Android 9 and 10; `msf:<n>` are files) cannot be placed exactly: such a folder is treated as possibly overlapping every shared folder in or around a Download folder (SEC-W2B-2; `msd:` recognised since p6/w2bdev, before it counted as overlapping every folder on the phone's storage). Folder pick-up says so in its own sentence (`PickUpSafety.FOLDER_DOWNLOADS_ENTRY_NEAR_WRITABLE`, `RUN_...`; another profile or the media list: `FOLDER_PLACE_UNKNOWN_NEAR_WRITABLE`, `RUN_...`), which WP10's Folder pick-up screen shows like the other refusals. A writable one then refuses changes while a read-only folder sits in Download ("Android does not tell this app where <folder> is, because it was shared through the folder picker's Downloads entry. ... Sharing <folder> through the phone's storage entry instead lets the app tell."; since p6/w2bres it names the folder Android does not place). On Android 9 and 10 the Downloads root picked as a folder is unknown against every folder of the phone's storage (B1-DL), and a pick-up rule in Download is refused while such a writable folder exists. The Folders screen could suggest picking through the phone's storage entry. | Conservative by design; the exact place is not in the id. |
| WP12 | `RunHost`: a write that was already inside the workspace when the run's time ran out is made and counted, and the script is told it "may have been done" (`RunHost.IN_FLIGHT`); the workspace then ends for the run. Attack list: a hostile process timing a write to straddle the deadline gets at most that one write, within the 20-file cap. | Interrupting a write mid-way would not stop it (LocalWorkspace writes on its own thread); counting it is the honest answer. |
| WP12 | The approval reminder alarm is exact only with "Alarms and reminders" (Android 12+); otherwise allow-while-idle, which Doze may hold back (about once per 9 minutes): the reminder can come a few minutes late. | Android's rule; the request still expires on time. |
| WP10 / WP14 | Added by the residual fixes (p6/w2bres, B1): a folder from another app's storage provider that names its folders by ids of its own (a cloud drive, some file managers) still counts as apart from the phone's folders for changes. If that app shows the phone's own files, agents could change a read-only folder through a writable folder on the other side. Folder pick-up treats such pairs as unknown and refuses; folders whose ids are paths on the phone's storage are compared by path and refused. | Blocking would stop every change in such folders whenever any folder is read-only. The Folders screen warns on both sides instead (`OwnerFolders.fromOtherAppStorage`, `otherAppStorageNote(appName, readOnly)`; WP10, handoff-w2bfix.md), and docs/LIMITATIONS.md section 6 says it plainly. |
